# Phase 4.3 — Boss Image Permissions and Identity Audit

Reviewed: 2026-11-08. Scope: **59 existing fight-level entries.**

## Actual outcome

- **59/59** fights have a stable, independently keyed image-manifest entry and a deliberately labeled branded fallback.
- **0** have a boss-specific portrait with both confirmed subject/variant identity **and** documented reuse permission.
- **0** source images were republished, embedded, scraped, re-encoded or presented as permitted.
- **59** use the website's existing `/phantom-guide-logo.png` as a decorative brand placeholder, clearly labeled **No verified boss image available**. This is not an image of the named boss.
- No third-party rights are inferred from “official,” public visibility, attribution, indexing status, or links on another fan site.

## Rights and source findings

1. [Official S-GAME media hub](https://pbz.s-game.com/en-US/) publishes screenshots and concept art, but its gallery does not establish a general reusable image licence for the site's individual boss portraits.
2. [S-GAME / PARAWULIN game EULA](https://pbz.s-game.com/eula/en-US/) restricts reproduction/display of game material without consent. We have not verified a separate exception, fan-media permission, press-grant or written permission for this specific website.
3. [pbz.gg boss directory](https://pbz.gg/bosses/) is a *research reference*, not a grant of re-publication rights for screenshots.
4. [AllThings.How boss index](https://allthings.how/phantom-blade-zero-bosses/) and existing linked encounter guides provide possible visual reference leads but do not transfer copyright permission to us.
5. [Steam game's publisher gallery](https://store.steampowered.com/app/4115450/Phantom_Blade_Zero/) provides official game imagery, but a publicly accessible product listing is not a permission statement for downloading or hosting individual game portraits.

**Result:** no approved boss portrait candidate. The correct publication decision is a clearly labeled fallback for each fight, while preserving the ability to add an individually reviewed and licensed image later.

## Implementation constraints and next steps

- `src/boss-images.js` contains one manifest record per boss and a deliberately empty, separately approved image registry. A proper entry requires exact `bossId` and `subjectId`, variant description, image source URL, rights holder attribution, permission evidence URL, permission basis, and intrinsic dimensions.
- `src/boss-image-ui.js` reserves layout, lazy-loads directory imagery, handles approved-image failures with a text fallback, and keeps the brand mark decorative with empty alt text.
- A future image can be added only after obtaining or establishing valid reuse permission, verifying the exact boss/variant, creating an optimized local image, and adding attribution. Shared group images require separately documented participant identity and rights.
- Do not auto-generate pseudo-gameplay portraits or substitute a different fight's screenshot.
- Do not enable indexing or advertising as a side effect of Phase 4.3.
- Permission approvals remain a manual editorial decision. No gameplay identity has been inferred from a thumbnail alone.

## Release interpretation

**Image system coverage: 59/59. Boss-portrait coverage: 0/59.** That difference must remain explicit in player-facing and release reporting.
